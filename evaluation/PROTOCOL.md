# Frozen evaluation protocol v1

Freeze inputs and labels before executing detectors or fitting the optional model. Do not tune production rules on the held-out split. Development-train captures contain benign traffic only; development-validation captures select an anomaly threshold. Split by complete capture and distinct source addresses, never event rows. All captures are originally constructed offline PCAPs processed by pinned Zeek 8.0.10. They are synthetic sensitivity/counterexample tests, not externally collected, blindly adjudicated or representative production accuracy data.

Rules are the unchanged phase2-rules-v1 snapshot. Evaluation uses actual collector normalization and production PostgreSQL apply/finalize/alert code in rolled-back transactions. Labels are separate files never sent to apply. Kafka delivery/recovery is tested separately on real infrastructure. Default indicators are fictional exact matches.

An episode match requires identical detector family/source/destination and overlapping contributing-event and labeled time intervals (inclusive endpoints, ten-second tolerance), with one-to-one matching. Predictions from overlapping windows remain one five-minute bucket episode. Duplicate predictions beyond one match are false positives. Authorized-scanner suppressions are installed before processing; suppressed predictions are reported separately and excluded from actionable precision. All misses and false positives remain in outputs. Unsupported horizontal scanning is reported separately from supported-family recall.

For the ML comparison, rules and ML both reduce to actionable source/five-minute-bucket episodes. A source is positive if a labeled suspicious supported or unsupported behavior occurs in that bucket. DNS/connection evidence are both included; no family attribution is inferred from an anomaly score. Use the same source-episode matching for rules, anomaly model and their union. Authorized scanning is an explicit policy exclusion for both paths. Report per-family rule metrics separately from this generic comparison.

ML features are nonoverlapping 60-second source windows: connection count, distinct destination count, distinct TCP ports, classified TCP failure ratio, completed DNS count, NXDOMAIN ratio and outgoing byte count, plus explicit missing-ratio flags. Numeric ratios with no denominator use zero and a missing flag; this is not a success observation. Isolation Forest training uses development-train benign windows only. No external pickle is loaded. Choose the strict anomaly cutoff from development-validation benign scores (maximum score, a zero observed benign-window false-positive objective); do not select it on held-out results. The JSON artifact exports tree structure and feature schema, seed, preprocessing and training hashes. Model remains an offline, opt-in experiment unless useful coverage is established.

Load tests use synthetic_fixture provenance and their own generator spec. Report attempted/acknowledged/unique persisted counts, elapsed publication/drain time, polling-based ingestion-to-durable-observation latency, broker lag, resources and recovery. Run repeated short distributed/hot-source trials with one and two workers, monitoring on. The 500 events/s, ten-minute engineering target can fail early if bounded backlog or drain limits are exceeded: explicitly report early failure and untested duration; never extrapolate a short run to sustained capacity. Producer stops accepting new inputs on that bound and drains acknowledged inputs. A synthetic receipt timestamp is not packet-capture delay or UI latency.
