# ML experiment v2 — frozen before fitting

This is a second, authored synthetic experiment, not a blind benchmark. The developer has seen v1 failures. All v2 captures use new PCAP bytes, distinct source addresses and seeds; holdout is fresh but shares generator families with development. No claim of independent real-world accuracy follows. V1 inputs, model and reports remain unchanged.

Generate 40 benign training captures (eight variants each of web, busy DNS, mixed failed connections, maintenance outage, and stale DNS); 20 validation captures (two of each benign family plus two of each fast scan, slow scan, horizontal scan, denied connections, and NXDOMAIN attack); 22 held-out captures (two of each benign family and attack family, one authorized scan, one fictional indicator). Complete captures are five minutes and use distinct sources across all splits. Offline original CC0 packets go through pinned Zeek 8.0.10 and actual Go normalization. Labels and IP identities never become features. Production rules remain phase2-rules-v1, evaluated using actual SQL code, without tuning.

Compare the v1 artifact on the new corpus, a retrained nine-feature baseline, and a retrained temporal model. Both retrained models use 128 trees, max_samples=min(256, train windows), seed 41, float32, no scaling, and benign training only. No algorithm or hyperparameter search after held-out scoring. Temporal features add trailing 180-second distinct TCP ports/destinations, failed TCP count, maximum five-second connection bin count, mean interarrival seconds and gap coefficient of variation. All history ends strictly at the scored minute's end; partial initial history is allowed. Empty minutes are retained, never oversampled.

Threshold candidates are the distinct validation scores plus a no-alert cutoff of 1.0. Select the candidate maximizing validation source-episode F1 subject to no more than one false-positive benign capture. Ties prefer fewer false positives, then the higher threshold. Report the complete validation precision/recall tradeoff and select once before scoring holdout. This permits a measured false-positive tradeoff rather than insisting on zero observed benign windows. Scores are not probabilities. Report both window and five-minute source-episode metrics; rules and union use identical source episodes, with authorized inventory scanning excluded by policy. Indicator identity is deliberately not a statistical feature.

Export JSON tree arrays and verify sklearn parity across all splits. Show training feature ranges, tree split counts, empty windows, all held-out scores/misses/false positives and additive coverage versus rules. A successful synthetic incremental result warrants only an offline prototype; it cannot authorize default runtime promotion. No external pickle, runtime model loading or UI accuracy claim is added. Report run status separately from usefulness. New tuning after seeing these results requires a third frozen protocol and fresh holdout.
