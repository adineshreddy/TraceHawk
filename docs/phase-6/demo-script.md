# Five-minute narrated demo script

The accompanying `tracehawk-demo.webm` is a shorter, silent automated screen walkthrough of the actual application. This script is for a human-narrated five-minute recording. Do not show the password file, `.env`, terminals containing credentials or GitHub authentication output. Start already signed in. Use fresh replay scopes; historical data can remain.

| Time | Show | Suggested narration |
|---|---|---|
| 0:00–0:35 | Overview and the controlled-replay banner | “TraceHawk is a distributed network security monitoring laboratory. It turns Zeek telemetry into explainable alerts and an analyst investigation workflow. The traffic shown here is constructed offline; the example threat indicators are fictional.” |
| 0:35–1:10 | Replay → controlled scenario → phase2-rules-v1 → 10× → Start | “A Go collector normalizes the telemetry and publishes it to Kafka. Two Python workers own three partitions. This scenario produces 108 persisted events and six alerts across port scans, failed connections, DNS NXDOMAIN bursts and exact indicator matches.” |
| 1:10–2:00 | Alerts → DNS filter → DNS NXDOMAIN burst → matching windows/evidence | “Each finding shows what crossed the threshold and the events supporting that decision. These are measured sliding windows in event time. The DNS finding has 40 supporting events, and I can inspect its timeline rather than relying on a score without evidence.” |
| 2:00–2:25 | Enter investigation reason → Acknowledge → source host | “Analyst decisions are recorded with a reason. Host investigation connects an alert to the source's other traffic and event timeline.” |
| 2:25–3:10 | Replay controlled scenario with Authorize lab scanner checked; inspect suppressed scan | “Authorization is an explicit policy. The scan is suppressed before processing, while its finding and 24 supporting connections remain visible. Suppression does not delete the evidence.” |
| 3:10–3:45 | Operations → worker ownership/checkpoints; optionally separate Grafana tab | “Database checkpoints and ownership fences let workers recover without duplicating final detection effects. The outbox publishes alert updates at least once, with stable IDs for deduplication. Recovery tests cover worker termination, broker and database outages. Prometheus and Grafana expose operational health.” |
| 3:45–4:10 | Replay benign scenario → completed, 17 events, zero alerts | “This benign baseline completes with 17 events and no alerts. It checks the basic pipeline, rather than establishing a real-world false-positive rate.” |
| 4:10–4:45 | Evaluation, then repository ML v2 report | “Evaluation includes misses and benign false positives. Two offline ML experiments were tested; the retrained models did not add useful held-out detections at their selected thresholds, so I kept them disabled. The 500-events-per-second, ten-minute load target also failed early and is documented.” |
| 4:45–5:00 | Architecture and repository links | “The repository includes a one-command local demo, pinned dependencies, CI, Kubernetes isolation and recovery checks, and reproducible evaluation inputs. The project demonstrates networking, distributed state, investigation workflows and evidence-based engineering decisions.” |

Recording checklist: keep a 1440×1000 or 1920×1080 browser viewport, close unrelated tabs/notifications, wait for completed runs, use the committed rule snapshot, and speak only to results in the reports. Pause the recording if services fail; fix and rerun the rehearsal. Do not present 40 events/s short trials as maximum capacity or synthetic recall as production accuracy.
